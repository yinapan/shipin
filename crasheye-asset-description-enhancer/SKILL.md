# Crasheye 资产描述完善

## 目标

把"游戏玩家""手机桌面""游戏 Boss 战场景"这类短描述，完善为可生成、可复用、可验收的资产描述。描述服务于整部动画的视觉统一，不写成宣传文案，也不把静态资产描述写成完整视频分镜。

## 统一风格

日系二维动画与数字绘景结合的科技叙事风格。人物使用适度动漫化的自然比例（6.5~7头身），五官完整、表情生动，保留发丝层次、服装褶皱和手部结构；线稿清晰且有粗细变化（外轮廓1.5~2px，内结构0.8~1px @1080p），赛璐璐明暗结合柔和渐变，形成明确体积感。

场景具有可信的空间透视和前中后景：桌面、电脑、人物与背景设备层次分明，背景细节丰富但不遮盖叙事主体。以深蓝、藏青为环境底色（#0A1929 ~ #0F1D2E），青蓝色屏幕光和全息界面作为主要科技视觉（#00E5CC ~ #2EC4F6），人物肤色保持自然，辅以暖色光形成冷暖对比。橙色表示问题/闪退，绿色表示验证通过，灰色表示旧流程。

画面16:9，主体清楚，预留后期字幕安全区。

## 先区分事实与补充

- 已确认事实：资产名称、剧本身份、用途、已确认服装/颜色/动作。
- 可以补充：构图、景别、轮廓、比例、光线、材质、背景密度、字幕留白和复用状态。
- 不得擅自确定：年龄、性别、肤色、发型、品牌 Logo、设备型号、版本号、真实数据和剧本没有依据的服装细节。

已有描述不为空时保留原意，只补齐视觉缺口，不改变资产身份和剧情功能。

## 角色锚点

以下为全片角色的外观锚点定义，描述完善时必须与之保持一致，不得偏离。

### 林（女工程师）

- 灰色工装夹克 + 橙色缝线点缀（拉链头、口袋边、袖口折叠处）；

- 身高约 165 cm，6.5～7 头身，微瘦体型；
- 表情范围：专注、蹙眉、微笑、如释重负——不做夸张颜艺；
- 职能：一线崩溃排查工程师，主视角角色。

### 陈（男主管）

- 黑色短发偏分，鬓角整洁；
- 深藏青色翻领 Polo 衫，左胸口袋别一支金属笔；

- 身高约 178 cm，与林身高比约 12:13；

### 用户（游戏玩家/App 使用者）

- 作为叙事代入角色出现，无固定外观；

- 服装跟随场景合理推断（居家休闲、通勤等），不做夸张造型。

### 精灵（AI 小精灵）

- 主色蓝绿 #00CDB8，采用与人物同一套二维绘制质感，通过半透明身体、柔和边缘光与局部高光表现科技属性；
- 水滴形头部，一只圆形大眼（瞳孔为亮青光点），无嘴；

- 胸前佩戴发光智能听诊器（听诊器头部有脉冲光环）；
- 全片唯一造型，任何镜头不得改变外形、配色或配件；
- **❌ 禁止**：红色眼睛、灰色/暗色调精灵、Q 版大头变体。

## 精灵动作语言

描述完善时，如果资产涉及精灵的动作或姿态，必须引用以下 6 种标准状态之一（可叠加），不得自创动作语义。

| 状态 | 视觉表现 |
|------|----------|
| 待机 | 微幅上下浮动，类似呼吸感的缓慢节律，翅膀半收 |
| 移动 | 飘浮滑行，身体微前倾，尾迹留淡青光线——非弹跳非行走 |
| 分析中 | 眼部亮度提升约 30%，听诊器头部脉冲发光，翅膀完全展开 |
| 发现线索 | 眼部快速闪烁 2–3 次，身体周围扩散一圈青绿脉冲光环 |
| 完成 | 翅膀舒展至最大，头部微点头，眼部柔和常亮 |
| 等待工程师 | 身体微侧，视线方向看向林（或陈），翅膀半收回待机幅度 |

## 描述结构

根据类型选取相关维度：

1. 身份与用途；
2. 主体外观、比例和识别特征；
3. 景别、构图、视角和前中后景；
4. 稳定姿态或可复用状态；
5. 色彩、主光方向、阴影和材质；
6. 与本文件内联角色锚点的连续性；
7. 字幕安全区、后期文字和负面约束。

每条建议 120–260 个中文字符，界面限制下不超过 300 字。先写主体和用途，再写视觉细节和约束。

## 类型规则

### 角色

写清身份、6.5～7 头身自然人体比例、脸型和发型（仅限已确认内容）、服装版型、表情基调、手部和常用姿态。角色设定优先半身或全身三分之二构图，确保发型、服装褶皱、鞋子和手部可复用。AI 小精灵保留扫描之眼和发光智能听诊器，亲切但不幼稚，不做大头 Q 版。

### 场景

写清空间用途、16:9 构图、视角、前中后景、主体位置、光源、背景密度、色彩分区和字幕留白。游戏、手机桌面、PC 软件和 Crasheye 后台使用抽象可读 UI，长文字交给后期。

### 道具

写清轮廓、尺寸关系、材质、主色、状态、配套角色/场景、可复用视角和字幕避让区。手机、游戏背包、崩溃提示、报告卡、候选原因卡和听诊器使用同一套细线稿与圆角结构。

### UI、图标和特效

写清信息层级、模块位置、图标语义、状态颜色、动画前后状态和安全区。只使用短标签或图形占位；闪退用短促橙色告警和应用退出状态表达，不用爆炸、火焰或服务端宕机视觉。

## UI / HUD 规范

描述完善涉及 UI 界面、HUD 叠层或数据面板类资产时，遵守以下规范：

- **底色与边框**：深色底（#1A1F2E 附近）+ 青绿 #00CDB8 边框，边框 1 px 带微发光（glow）效果；
- **圆角**：统一 8 px；
- **语言**：全中文标签，不使用英文占位符；
- **候选卡片措辞**：使用"嫌疑最大""可能性较高"等中文表述，**❌ 不用**"置信度高""Confidence"；
- **核验标记**：右上角保留"待工程师核验"角标；
- **对比分屏**：左侧灰调 #2A3040（修复前）、右侧蓝调 #0A2A4A（修复后），右侧整体亮度高于左侧约 20%，分屏中线清晰，两侧标签为中文（如"修复前""修复后"）；
- **品牌拼写**：Crasheye——首字母大写，其余小写，全片唯一拼法；
- **❌ 禁止**：乱码、假英文 Lorem ipsum、随机 Logo、无意义数字串。

## 色调曲线

描述完善时，需标注资产所属幕次，并使色调描述与以下曲线对齐。

| 幕次 | 镜头范围 | 色调方向 |
|------|----------|----------|
| 第一幕（问题爆发） | 镜头 1–4 | 整体明度降低约 10%，偏冷暗色调；闪退瞬间以橙红闪光打破暗面 |
| 第二幕（AI 分析） | 镜头 5–6 | 画面渐亮，AI 分析空间整体亮度提升约 15%，青绿主导 |
| 第三幕（修复验证） | 镜头 7–9 | 全片最高明度；对比分屏左灰右蓝、右侧亮度再高约 20%；收尾暖白光，情绪释放 |

跨幕资产复用时，同一资产应提供不同幕次的色调变体说明。

## 字幕与字体规范

描述完善涉及字幕、文字叠层或品牌文字时，引用以下字体规格：

| 用途 | 字体 | 字号 | 位置与动效 |
|------|------|------|------------|
| 常规字幕 | 思源黑体 Regular | 36 px | 底部居中，淡入 0.3 s |
| 强调字幕 | 思源黑体 Bold + 青绿色 #00CDB8 | 40 px | 底部居中，淡入 0.3 s |
| UI 标签 | 思源黑体 Medium | 28 px | 跟随 UI 模块位置 |
| 数据标注 | 思源黑体 Light | 22 px（≥ 正文 60%） | 跟随数据图表位置 |
| 品牌粒子汇聚 | 思源黑体 Bold | 72 px | 画面中央，粒子汇聚成字 |
| 弹幕/滚动信息 | 思源黑体 Regular | 24 px，透明度 60% | 右→左滚动 |

描述中不需要写出具体 px 值，但需指明文字层级（常规/强调/标签/标注/品牌/弹幕），以便后期对照此表排版。

## 转场规范

描述完善涉及镜头衔接或场景过渡时，遵守以下规则：

- **镜头间**：淡入淡出（dissolve），时长 0.5–0.8 s；
- **场景内**：运动跟随（camera follow），镜头随主体平滑移动；
- **进入 AI 空间**：精灵引导 + 渐变过渡，从现实色调渐变至青绿 AI 空间色调；
- **幕间切换（Phase 间）**：快闪切（flash cut），0.3 s，伴随短促音效提示；
- **❌ 禁止**：硬切黑屏、花式擦除（星形/百叶窗等）、无过渡直接跳转。

## 数据标注规范

描述完善涉及数据图表、数值面板或趋势曲线时，遵守以下规则：

- 所有数据旁标注"**\*示意数据**"或"**\*预期效果示意**"；
- 趋势曲线中的预期/目标部分使用**虚线**绘制，旁注"预期趋势"；
- **❌ 禁止**使用具体数字（如 1247 次、3 分钟、98%、¥12,000 等），一律用模糊表述（如"显著下降""大幅缩短""趋近于零"）或示意图形代替；
- 图表坐标轴使用中文标签，不标具体刻度数值。

## 统一风格检查

1. 缩略图中能识别主体。
2. 同类资产的线稿、6.5～7 头身自然比例、面部结构、服装细节、色板和光影一致。
3. 画面有字幕安全区，正式文字由后期排版。
4. 没有以下任何一项违规：避免极简扁平矢量、大头儿童卡通、黑点眼睛、粗黑等宽描边、写实摄影、明显三维塑料质感、遮挡人物的过度光效、纯色无细节背景、AI生成乱码/假英文、红眼/暗色精灵、英文标签（BEFORE/AFTER等）、品牌错字（Crasheye唯一拼法）、同角色跨镜头换脸换衣、水印。
5. AI 只输出候选方向，工程师负责核验、修复、测试和发布。

## 输出

批量完善时按输入顺序返回合法 JSON 数组：

```json
{
  "asset_id": "已有 ID；没有时生成稳定英文或拼音 ID",
  "name": "资产名称",
  "asset_type": "character|scene|prop|ui|icon|effect",
  "enhanced_description": "120–260 字的精细描述",
  "keep_from_source": "保留的原始事实",
  "needs_review": ["需要确认的信息"]
}
```

若宿主界面只接受一列文本，只输出与输入资产一一对应的 `enhanced_description`，不加解释。不要输出模型参数、路径、节点 ID 或虚构事实。
