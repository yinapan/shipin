# 视频整理与制作经验规则

适用项目：CrasheyeMV。记录日期：2026-11-06。

本规则以用户认可的 `output/crasheye_4k_final_v3.mp4` 为实例，供后续视频处理复用。复用剪辑方法、声音一致性和验收标准；新一批素材的文案、时长、切点与声音参数必须重新确定。用户当次明确要求优先。

## 1. 先核实素材，再排时间轴

1. 列出本批视频与音频，核对数量、数字顺序、时长、分辨率、帧率、画幅、采样率、声道及有无原声轨。按自然数字顺序处理 `_1 → _2 → _3`，避免把 `_10` 排在 `_2` 前面。
   分集存放时，先按外层文件夹“第 1 集、第 2 集、第 3 集……”排序，再按每集内部的 `shot0010、shot0020、shot0030……` 排序。不要全局按 shot 排序，也不要用文件名里的 `sc` 编号替代外层集数。2026-11-07 完整版已按用户明确要求采用这一顺序。
2. 视频抽取开头、中间、结尾和转场附近的画面；必要时分析相邻帧变化，区分有效动作与几乎静止的尾段。
3. 配音核实实际说了什么。可用本地语音识别辅助，结合准确文稿修正识别误差。文件名只作线索，不作为内容证据。
4. 对照用户文案，检查缺句、重复句、错序和文件名不符。不要仅因文件名不同就断定缺配音，也不要把重复音频当成新内容。
5. 在清楚的既定要求内直接推进。若确实缺配音或文案冲突，说明具体缺哪句及可执行的处理方式，再集中确认必要的内容决定；不能静默删句或默认把无声字幕当成已完成配音。

经验：本次第一段音频的文件名含旧文案，实际声音却符合最终第一句。必须检查音频内容后再作判断。

## 2. 按叙事短句对齐镜头

- 保留用户要求的视频顺序，以语义和动作作为切点依据。
- 同一音频可以跨镜头：本次第二段配音的前半句对应第二段画面，“再打开，可能又崩了”对应第三段画面。
- 以配音中的词句边界对齐“点击、闪退、再打开、再次崩溃”等关键动作，避免画面事件明显早于或晚于讲述。
- 优先保持原配音的自然语速；先调整画面可用范围和节奏，不默认加快人声来迁就视频。
- 把切点量化到实际输出帧率的帧边界；逐句检查，而不是只比较总时长。
- 时长由内容和自然收尾决定，不固定为本次的 14.67 秒，也不要求每个镜头等长。

## 3. 处理音频较长与画面停顿

### 默认处理顺序

1. 找出原视频真正有动作的范围，裁去无叙事作用的静止尾段。
2. 根据对应短句的时长，适度放慢或加快有效动作。
3. 慢放时按需要做光流插帧，保持运动连贯；重点检查快速闪光、手指、文字、人物边缘与转场是否扭曲或重影。
4. 对相邻镜头的切点作小幅调整，缩短不必要的句间空白。
5. 若仍不足以自然覆盖配音，重新安排镜头或说明需要补充素材，不能用数秒定格掩盖缺口。

### 不再采用的做法

- 直接把每段原视频从头播到尾，再复制末帧，直到配音结束。
- 只删除新增定格，却保留原片里长时间几乎不动的尾部。
- 仅靠轻微镜头缩放假装原有长时间停顿已经解决。
- 过度慢放、反复倒放或循环人物动作，导致明显不自然。

技术上用于光流前后帧计算的极短缓冲可以保留，但不能变成观众可感知的长时间停留。本次前两段分别取原片约 0–1.875 秒与 0–2.75 秒的有效动作，补帧后覆盖约 5.25 秒与 5.208 秒；这些范围仅适用于本次素材。

## 4. 补配音以原声音为参考

- 原有配音是本批视频的声音基准。需要补一句时，优先使用同一说话人的原录音；用户要求合成时，使用主配音音频与准确逐字稿作参考生成。
- 不能仅选择“男声”、调低音高或统一音量，就认为声音已经一致。还要匹配音色、音高范围、语速、句间停顿、语气与录音质感。
- 不擅自更换整段原配音。只补当前需要的句子，保留用户已有声音。
- 可生成多个候选，检查字词完整、发音、尾音和自然度，再比较与参考音频的声音特征。音高和说话人向量仅作辅助，不能把余弦分数直接写成“相似度百分比”，也不能替代试听。
- 不将未实际试听的结果描述成“已听过”或“完全同声”。当前用户认可的成片可作为后续实际效果参考。
- 裁除首尾多余静音时保留辅音和自然尾音，避免切字；必要时做极短淡入淡出。
- 将补配音与原声统一响度、峰值和采样率，避免结尾突然变响、变尖或像换了讲述者。
- 新一批配音若更换了说话人，就改用该批的参考录音，不沿用本次声音。

### 本次有效实现

本地使用 Qwen3-TTS-12Hz-0.6B-Base，以两段原配音及其准确文稿进行参考生成。候选种子为 7、19、31，本次选择 31，对应句子“这，就是软件崩溃。”，约 1.84 秒。

这组种子、时长和语速不是未来所有视频的固定值。新任务应重新检查候选。相比上版直接使用默认男声，本次改为使用真实原配音作参考，用户认可了最终声音与画面的整体效果。

## 5. 字幕样式与分句

- 字幕文本与最终确认的配音、剪辑文案一致，按自然短句出现，避免一大段字幕长期不变。
- 默认底部居中、白色正文、深色描边与轻阴影；重点词用暖黄色加粗。重点内容按新视频语义确定，不固定为本次的“闪退了”“软件崩溃”。
- 保持安全边距，检查画面自带文字、按钮、手机 UI 和字幕之间是否互相遮挡。长句应自然拆分，不能挤出画幅。
- 先检查原片是否已经烧录旁白字幕。避免新旧两行重复显示；必要时采用保留主体、保持画幅比例的轻微裁切，或仅清理旧字幕所在的小范围，再统一新字幕。清理后要检查是否留下可见模糊块或修补痕迹。片尾有资质或品牌小字时，单独调整新字幕位置，不直接盖住原文。
- 字幕随配音出现、切换和结束；不要在有配音的句子尚未说完时提前移除。
- 本次 4K 样式可作为起点：微软雅黑，字号 112，描边 7，阴影 3，左右边距 220，底部边距 155，暖黄色 ASS 色值 `&H0000BFFF&`。新画幅或新构图需要重新检查，不能只照搬数值。
- 交付烧录字幕的 MP4，同时保存可编辑 ASS 和通用 SRT。

## 6. 4K 画面与导出

| 项目 | 本项目默认起点 |
| --- | --- |
| 横屏尺寸 | 3840×2160，保持比例，不拉伸主体 |
| 帧率 | 优先保留素材帧率；混合帧率时先确定统一时间轴 |
| 720p 放大 | Lanczos 缩放，适度锐化，避免描边、光晕和噪点加重 |
| 本次锐化参数 | `unsharp=5:5:0.35:5:5:0`，按新素材质量调整 |
| 视频格式 | MP4 / H.264 / yuv420p |
| 编码起点 | libx264，CRF 16，preset medium |
| 音频格式 | AAC，48kHz，192kbps；本次交付为双声道 |
| 响度起点 | `loudnorm=I=-16:TP=-1.5:LRA=7`，检查原声与新增配音的衔接 |
| 播放优化 | `+faststart` |

这些是已验证的起点，不是所有素材的绝对最优值。放大至 4K 不等于恢复真实 4K 拍摄细节；优先从原始素材制作，减少重复有损编码。

音频在重采样、响度处理和拼接后，应重建连续时间戳，例如使用 `asetpts=N/SR/TB`；必要时按采样点数裁切或补静音。不能只凭字幕时间表认定最终声音已同步。本次曾发现处理后结尾声音提前约 59 毫秒，重建时间戳后通过最终文件波形对齐核验。

## 7. 结尾规则

- 按用户确认的最后一句结束，句号收尾，保留自然尾音与很短的呼吸空间。
- 不追加未要求的解释字幕、长时间静止画面、音乐、片尾或标识。
- 本次最后一句为“这，就是软件崩溃。”；“正在用的程序，突然自己关了。”已从新增字幕和后续剪辑中删除。画面原生自带文字与新增字幕要分别判断，不能误认成同一层。

## 8. 交付前检查实际成片

1. **文件与规格**：读取最终 MP4，确认尺寸、帧率、时长、音视频轨和文件可正常读取。
2. **顺序与动作**：核对镜头顺序、关键动作切点、变速与补帧质量。检查原片尾部和镜头接缝，不只检查是否有完全重复帧。
   分集视频除了检查清单排序，还要核对实际成片里的镜头图像与对应素材，防止清单正确、拼接文件顺序却错误。
3. **声音**：确认原配音完整，新配音文案准确，没有漏字、重复、切尾、突兀静音或明显音量跳变。语音识别仅作辅助。
4. **同步**：按最终文件核对句子与画面的切点。必要时将导出的声音与原录音做波形对齐；允许有损编码造成微小采样差异，但不能用放宽阈值掩盖实际偏移。
5. **字幕**：核对分句、标点、重点词样式、字体、位置、边距，检查开头、转场、重点词与最后一帧。
6. **完整性**：完整解码音频和视频，检查错误及异常结束；抽帧检查和实际播放相互补充。未实际播放试听时，应准确说明所做的检查。
7. **证据**：记录输入文件、实际时间轴、处理方式、版本和核验结果。旧 JSON、旧截图或脚本参数不能代替对新导出文件的检查。

技术检查无法完全代替主观的运动自然度和声音衔接感。用户反馈应沉淀为新规则；不要仅因数值达标就否定用户感受。

## 9. 项目组织与后续使用

- `mp4/`：视频原素材，保留原件。
- `wav/`：用户配音原素材，保留原件。
- `work/`：中间文件、处理脚本、本地声音模型与环境、日志。
- `output/`：成片、ASS/SRT、需要交付的补配音、处理记录与核验证据。
- 不混用不同批次的素材。每次开始先明确本批输入清单；必要时按视频批次划分目录。
- 成片按批次与版本命名，保留已交付版本，不默认覆盖。当前认可版本为 `crasheye_4k_final_v3.mp4`。
- 现有脚本包含本次硬编码时刻、文件名和前版字幕文件依赖。后续应据实际素材适配，不能把旧脚本当作无需调整的通用工具。
- 模型与运行环境已在本地保留。需要补配音时优先复用经检查可用的环境，避免重复下载大文件或修改系统 Python 环境。
- 交付时提供新版成片的绝对路径链接，并简要说明实质修改和核验结果。
