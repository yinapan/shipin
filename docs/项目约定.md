# 本项目的视频制作约定

后续在本项目内整理、拼接、配音、加字幕和导出视频时，先阅读 [VIDEO_WORKFLOW.md](VIDEO_WORKFLOW.md)，按其中规则执行。用户当前明确要求优先。

## 用户已确认的标准

- 视觉与声音参考：`output/crasheye_4k_final_v3.mp4`。这是用户认可的版本，v1、v2 为历史试稿。
- 默认横屏 4K（3840×2160），保持画面比例；本次素材与成片均为 24fps。新素材先检查帧率，不机械改为 24fps。
- 按用户指定或文件名中的数字顺序拼接；配音要核实实际内容，不能只根据文件名判断。
- 素材分集存放时，严格先按外层文件夹“第1集、第2集、第3集……”自然数字排序，再在每集内部按 `shot0010、shot0020……` 排序；文件名中的 `sc` 编号不能替代外层集数。
- 以叙事和语音中的短句安排镜头。同一音频可以跨多个镜头，不要求“一段音频对应一个视频”。
- 不用长时间复制末帧凑配音时长。先识别并裁去原素材的静止尾段，再对有效动作适度变速、必要时光流补帧。
- 保留原配音的自然语速。用户要求补配音时，用主配音的真实音频及准确文稿作声音参考，匹配音色、语速、停顿与音量；不要直接换成无关的默认男声。
- 字幕跟随实际语音分短句，底部居中，白字深色描边，重点词用暖黄色加粗；避免遮挡画面关键信息。
- 结尾简洁。最后一句说完，保留自然尾音即结束；不自动追加解释、片尾或长时间空镜。
- 保留原素材和已交付版本，新版独立命名。交付前核验实际导出文件的画面运动、声音内容、同步、字幕与完整解码。

## 执行入口

- 完整规则、参数、经验与检查项：`VIDEO_WORKFLOW.md`。
- 本次成功实现：`work/retime_motion.py`、`work/clone_ending.py`、`work/render_v3.py`。
- 本次核验：`work/check_motion_edit.py`、`work/verify_voice_match.py`、`work/verify_v3.py`。
- 本地声音生成环境：`work/voice_env/Scripts/python.exe`；模型：`work/voice_model/`。
- 上述脚本包含本次素材名、时间点及路径依赖，属于参考实现。新视频必须重新检查素材、构建时间轴并适配脚本，不能直接覆盖重跑。

## 沟通习惯

常规剪辑、样式与编码选择按已确认规则直接推进。仅在素材内容或用户要求存在无法判断的冲突时集中澄清，不重复确认已经明确的偏好。进度更新应说明发现、已完成的工作或尚待解决的问题。
